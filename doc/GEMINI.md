## 2026-05-07 更新内容 #107 (旧静的HTMLの完全復元とHexo配信運用の再定義)
### 担当モデル: Codex

### 【1. 目的】
- Hexo移行後に旧サイトのレイアウトやテキストが正しく反映されていない問題を解消する。
- `legacy/html` に残っている旧HTMLを正として、`source/` 配下の移行先ページを旧サイトの状態へ完全再現する。
- 復元後の構成、デプロイ手順、今後の運用方法をドキュメントへ反映する。

### 【2. 実施内容】
- `legacy/html/*.html` を `source/*.html` へ復元し、ルート直下URLの旧ページを再現した。
- ツール系HTMLを `source/tools/*.html` にも複製し、`/tools/` 配下URLでも参照できるようにした。
- `tools-index.html` を `source/tools/index.html` として配置し、`/tools/` の一覧ページ互換を確保した。
- `metadata-cleaner.html` を `source/tools/metadata-eraser.html` としても配置し、移行後ファイル名との互換を確保した。
- 旧HTMLが参照する `../styles/...` と `../public/...` を維持するため、`legacy/styles` と `legacy/public` をそれぞれ `source/styles` と `source/public` へ復元した。
- 旧Markdown移行ページと `hello-world` 投稿は、同一URL出力との衝突を避けるため削除した。
- `_config.yml` の `skip_render` を更新し、旧HTML/CSS/アセットをHexoで加工せずそのまま出力する運用へ変更した。

```yaml
skip_render:
  - '*.html'
  - 'tools/*.html'
  - 'styles/*.css'
  - 'public/*'
```

### 【3. 検証】
- `npm run clean` と `npm run build` が成功することを確認した。
- 生成後の `public/*.html` が `legacy/html/*.html` とSHA256で一致することを確認した。
- 生成後の `public/tools/*.html` が対応する `legacy/html/*.html` とSHA256で一致することを確認した。
- `public/styles` と `public/public` の出力が `legacy/styles`、`legacy/public` と一致することを確認した。
- ローカルサーバーを `http://localhost:4000/` で起動し、トップページ、代表ツールページ、CSS、画像アセットが `200` を返すことを確認した。

### 【4. デプロイ】
- Cloudflare Pages の `volcane` プロジェクトへ Wrangler Direct Upload でデプロイした。
- 実行コマンド:

```bash
npm run clean
npm run build
npx wrangler pages deploy public --project-name volcane
```

- デプロイ結果:
  - Production URL: `https://volcane.pages.dev/`
  - Preview URL: `https://83238d6e.volcane.pages.dev`
- 本番確認:
  - `https://volcane.pages.dev/` が `200`
  - `https://volcane.pages.dev/background-remover` が `200`
  - `https://volcane.pages.dev/tools/background-remover` が `200`
  - `https://volcane.pages.dev/styles/style.css` が `200`
- `.html` 付きURLは Cloudflare Pages 側で拡張子なしURLへ `308 Permanent Redirect` されることを確認した。これは異常ではなく、最終URLで `200` が返れば正常。

### 【5. ドキュメント更新】
- `doc/ARCHITECTURE.md` を全面更新し、現行の「旧HTMLを正とし、Hexoは静的ファイルのビルド/デプロイ基盤として使う」構成を反映した。
- `doc/DEPLOYMENT.md` を全面更新し、Wrangler Direct Upload による現行デプロイ手順、確認方法、`npm run deploy` を使わない注意点を明記した。

### 【6. 現在の運用ルール】
- 完全再現を維持する間は `_config.yml` の `skip_render` を外さない。
- `source/*.html`、`source/tools/*.html`、`source/styles/`、`source/public/` は現行配信に必須。
- `public/`、`db.json`、`node_modules/`、`.wrangler/tmp/` は再生成可能。
- `legacy/` は復元元バックアップとして残す。
- ページ変更後は必ず `npm run clean`、`npm run build`、ローカル確認、Wranglerデプロイの順に進める。

## 2026-05-07 更新内容 #106 (ツールポータル UIの重複解消とMarkdownインデント修正)
### 担当モデル: Gemini 3.1 Pro (High)

### 【1. このセッションの目的と成果】
- **目的**: `/tools/index.html` のメインコンテンツが重複して表示される問題、および各ツールページでHTMLタグがそのまま表示される問題（Markdownパーサーの誤作動）を解決する。
- **成果**:
    - `tool_index.ejs` を簡素化し、ハードコードされていたHeroセクションを削除。コンテンツの制御をMarkdownファイル (`index.md`) 側へ完全に移譲することで重複を解消。
    - `webp-converter.md` などの主要ツールや `index.md`, `ai-magic.md`, `converters.md` において、HTMLタグの先頭に存在した4スペース以上のインデントを削除。Hexo (marked) がコードブロック `<pre><code>` として誤認識する問題を解消。
    - Cloudflare Pagesへの最終デプロイ (`npx wrangler pages deploy`) を実行し、完全な2カラムレイアウト・ライトテーマの再現を確認。

### 【2. 決定事項】
- **HexoにおけるHTML記述ルール**: Markdownファイル内に直接HTMLを記述する際は、絶対に4スペース以上のインデントを行わない。インデントを使用するとコードブロックとしてレンダリングされてしまうため、タグは行頭から記述することを徹底する。
- **テンプレートとコンテンツの分離**: `tool_index.ejs` などのレイアウトテンプレートには固定のHTMLコンテンツを記述せず、枠組みのみを提供する。具体的なコンテンツはMarkdown側に集約することで柔軟性を高める。
